# 项目开发规范

## 1. 核心技术栈

框架：Next.js ^15.0.0、React 19.2.14、TypeScript ^5.3.3
关键依赖：jsonwebtoken、postgres、zod、jose
开发工具：vitest、tailwindcss、eslint、swagger-ui-react

## 2. 测试框架的详细要求

### 测试框架
- 使用 vitest 作为测试框架
- 测试文件应放在 `tests` 目录下
- 测试文件命名规范：`*.test.ts`

### 测试要求
1. 所有数据库操作必须有对应的测试用例
2. 所有 API 接口必须有对应的测试用例
3. 测试用例应覆盖正常场景和异常场景
4. 测试前应确保数据库连接正常，测试后应清理测试数据

## 3. 禁止使用的 API

1. 禁止直接使用 Node.js 内置的 `fs`、`path` 等模块，应使用 Next.js 提供的 API
2. 禁止在客户端组件中使用 `getServerSideProps`、`getStaticProps` 等服务端 API
3. 禁止使用 `eval()`、`new Function()` 等动态执行代码的 API
4. 禁止使用 `require()` 引入模块，应使用 ES6 的 `import`
5. 禁止在 API 路由中直接操作数据库，应通过 `lib` 目录下的工具函数

## 4. 常用工具存放位置及使用规范

### 工具存放位置

- 常用工具存放在 `lib` 目录下,在编写数据库相关内容、认证相关、数据验证相关内容时优先检查工具目录内的工具

### 工具使用规范
1. **数据库操作**：必须通过 `db/client.ts` 中的 `sql` 函数执行，禁止直接创建新的数据库连接
2. **认证验证**：必须使用 `lib/middleware.ts` 中的 `withAuth` 函数进行 token 验证
3. **数据验证**：必须使用 `lib/validators.ts` 中的验证函数进行数据校验
4. **业务逻辑**：应将复杂的业务逻辑封装到 `lib` 目录下的工具函数中，API 路由只负责请求处理和响应

## 5. 其他开发规范

1. **代码风格**：遵循 ESLint 规则，保持代码风格一致
2. **类型安全**：充分利用 TypeScript 的类型系统，确保类型安全
3. **错误处理**：所有异步操作必须有适当的错误处理
4. **代码注释**：关键代码应添加适当的注释，解释代码的用途和逻辑
5. **工具复用优先**：开发过程中优先调用项目已实现的工具 / 函数 / 类，禁止对已有工具覆盖的逻辑进行硬编码；若现有工具无法满足需求，优先通过封装、扩展现有工具的方式实现，而非重写核心逻辑；调用现有工具时需在代码注释中标注复用工具的名称及用途，便于追溯和维护。

## 8. 项目结构规范

1. **API 路由**：存放在 `app/api` 目录下，按照功能模块组织
2. **页面组件**：存放在 `app` 目录下，按照路由结构组织
3. **工具函数**：存放在 `lib` 目录下，按照功能类型组织
4. **数据库相关**：存放在 `db` 目录下，包括 schema 和客户端
5. **测试文件**：存放在 `tests` 目录下，与被测试文件对应

通过遵循以上规范，可以确保项目代码的一致性、可维护性和可靠性，提高开发效率和代码质量。
