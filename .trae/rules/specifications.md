# 项目开发规范

## 核心技术栈

框架：Next.js ^15.0.0、React 19.2.14、TypeScript ^5.3.3
关键依赖：jsonwebtoken、postgres、zod、jose
开发工具：vitest、tailwindcss、eslint、swagger-ui-react

### 工具存放位置

- 常用工具存放在 `lib` 目录下,在编写数据库相关内容、认证相关、数据验证相关内容时优先检查工具目录内的工具

### 工具使用规范

1. **数据库操作**：必须通过 `db/client.ts` 中的 `sql` 函数执行，禁止直接创建新的数据库连接
2. **认证验证**：必须使用 `lib/middleware.ts` 中的 `withAuth` 函数进行 token 验证
3. **数据验证**：必须使用 `lib/validators.ts` 中的验证函数进行数据校验
4. **业务逻辑**：应将复杂的业务逻辑封装到 `lib` 目录下的工具函数中，API 路由只负责请求处理和响应

## 项目结构规范

1. **API 路由**：存放在 `app/api` 目录下，按照功能模块组织
2. **页面组件**：存放在 `app` 目录下，按照路由结构组织
3. **工具函数**：存放在 `lib` 目录下，按照功能类型组织
4. **数据库相关**：存放在 `db` 目录下，包括 schema 和客户端
5. **测试文件**：存放在 `tests` 目录下，与被测试文件对应

## 其他规范

所有沟通、所有的代码注释、文档全部使用中文，除非明确说明了使用中文写文档和注释，新文件使用 UTF-8（无 BOM）。  
所有函数名，变量名，文件名一律使用英文命名。  
所有对数据库结构的修改，直接修改 `db/schema.sql` 文件，禁止直接对数据库连接进行操作。  
禁用一切 CI/CD 自动化；构建、测试、发布必须人工操作。  

每次编写完TS代码都使用ESLint进行代码检查，确保代码质量。
所有查表操作都必须限制单次查询的记录数，避免返回大量数据。必要时，可以使用分页查询。

在编写UI时，请在可能复用的部分，提取为独立的组件，避免重复代码。
